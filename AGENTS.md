# AGENTS.md

This repository is a Firefox-first fork of the Mullvad Browser Extension. The goal is to keep the useful Mullvad integration, while improving the experience for standard Firefox users instead of optimizing primarily for the bundled Mullvad Browser environment.

Use this file as the quick-start guide. Deeper project notes live in `.agent/`.

Versioning model for this fork:

- FoxEnhanced patch version: `0.0.1`
- upstream Mullvad extension version: inherited from upstream `package.json` and manifest
- treat this repository as a patch set on top of the latest upstream Mullvad extension updates

Keep FoxEnhanced patch metadata in separate fork-owned files where possible. Avoid editing the
upstream version fields unless syncing from Mullvad.

Agent/docs file policy:

- `AGENTS.md` and files under `.agent/` should be maintained by hand, not generated by scripts or build steps.
- Keep these files concise, reviewable, and easy to diff during upstream merges.
- If guidance changes, update the existing files instead of replacing them with auto-generated output.

## Project Intent

- Preserve the extension's core value: help users understand their Mullvad VPN state, privacy posture, and proxy options from inside Firefox.
- Prefer Firefox desktop workflows and browser behavior when making product or technical decisions.
- Treat compatibility with Mullvad Browser as nice to keep when practical, but not as the primary product constraint for this fork.
- Keep `main` aligned with the latest official Mullvad extension updates and maintain FoxEnhanced work as a focused layer of patches on top.

## Environment

- Node.js: `24.11.0` or newer
- npm: `11.6.1` or newer
- Target browser for development: Firefox desktop

If `nvm` is installed, run:

```bash
nvm use
```

Install dependencies with:

```bash
npm install
```

## Core Commands

Development:

```bash
npm run dev
npm start
```

- `npm run dev` starts Vite in watch mode and regenerates extension assets.
- `npm start` launches Firefox with the local extension loaded from `extension/`.

Quality checks:

```bash
npm run lint
npm run tsc
npm test
```

Build and packaging:

```bash
npm run build
npm run pack:xpi
```

- `npm run build` prepares the production extension in `extension/`.
- `npm run pack:xpi` creates the installable Firefox package in the repo root.

CI parity:

```bash
npm run lint && npm run tsc && npm test && npm run build
```

## Development Rules

- Do feature work in `src/`, not in `extension/`.
- Treat `extension/manifest.json`, `extension/README.md`, `extension/LICENSE.md`, and `extension/dist/` as generated/package output.
- Update `src/manifest.ts` when manifest behavior needs to change.
- Keep Firefox as the default mental model when reviewing UX and API choices.
- Prefer small, testable changes in composables/helpers before pushing more logic into Vue components.
- Add or update Vitest coverage when changing reusable logic, sorting, proxy helpers, or location/recommendation behavior.

## Commit Guidance

- Commit focused, reviewable changes rather than broad mixed-purpose edits.
- Prefer commit messages that describe the user-facing or maintenance outcome, not just the files touched.
- When possible, keep FoxEnhanced-specific patches isolated from upstream sync commits.
- Before committing, exclude local-only files such as `.codex` and other personal workspace artifacts.

## How the Project Is Structured

- `src/popup/`: popup app shown from the browser toolbar button
- `src/options/`: full options/settings page
- `src/background/`: background page and browser event wiring
- `src/components/`: shared Vue UI components used across views
- `src/composables/`: reusable stateful logic and browser-facing hooks
- `src/helpers/`: lower-level browser API, proxy, tab, and utility code
- `src/styles/`: shared styling entrypoint and theme overrides
- `scripts/`: manifest generation and packaging preparation scripts
- `extension/`: assembled extension package used by `web-ext` and packaging commands

## Upstream Organization Summary

The Mullvad team organized the original project around three entrypoints and a packaging pipeline:

- UI entrypoints are split into `popup`, `options`, and `background`.
- Shared behavior is pushed into composables and helpers instead of being duplicated in each view.
- Vite builds the web assets into `extension/dist/`.
- Node scripts generate `extension/manifest.json` and copy top-level docs into `extension/`.
- `web-ext` then runs or packages the completed `extension/` folder.

That structure is worth keeping. For this fork, the main adjustment is product direction: bias implementation and testing toward regular Firefox usage patterns.
